# AGENTS.md
## Technical Interface and Repository Context for SSTracker

This document defines the systemic constraints, development guidelines, database schemas, and architectural boundaries of the **SSTracker SaaS platform**. All autonomous AI agents (Google Jules, Google Antigravity, and subagents) are strictly required to read, parse, and enforce these specifications prior to generating plans or committing any edits.

---

### 1. Technological Stack & Environment Specifications
* **Framework**: Svelte 5 & SvelteKit (Runes-based reactivity model) [688].
* **Backend Platform**: Firebase Modular SDK v12, Firebase Admin SDK, Cloud Functions [688].
* **Data Plane**: Cloud Firestore and Firebase Realtime Database (RTDB) [688].
* **Runtime**: Multi-codebase architecture split across 7 specific repositories [560, 561].
* **Package Manager**: pnpm [113].

### 3. Critical Global Constraints & Architectural Gates
Any code modifications generated by autonomous agents must immediately satisfy these static validation checks [112]:
1. **80-Line Function Limit**: No function body can exceed 80 lines [112]. Extract heavy logic into utility modules (`src/lib/utils/` or helper scripts) [112].
2. **Strict Svelte 5 Reactivity**: Legacy Svelte 4 reactivity syntax is banned [112]. Use `$state`, `$derived`, and `$effect` runes explicitly [56, 112].
3. **Infinite Loop Prevention**: Programmatic navigation (`goto`) or state mutations inside `$effect` runes must be safely wrapped in `untrack()` closures [112].
4. **"B815 Defensive Hydration" Guard**: Every raw Firestore query (e.g., `getDocs` or `onSnapshot`) must be guarded by an early-return check to prevent infinite loops and quota burns: `if (!db || !authStore.isAuthenticated) return;` [112].
5. **No Global-Scope Network Calls**: Database/external connections (Stripe/Admin SDK initialize) must reside strictly within individual function execution blocks, avoiding global instantiation timeouts [563, 588].

### 4. Zero-Trust Data Plane & Multi-Tenancy Rules
SSTracker operates on a cell-isolated, multi-tenant Postgres and Firestore architecture [557, 566]:
* **Multi-Tenant Claims**: All read/write operations on tenant resources must match the user's custom claim `request.auth.token.clubId == clubId` [533, 566].
* **Collection Paths**: Core schemas must strictly adhere to the following routing:
  * `/tenants/{tenantId}` [689]
  * `/devices/{deviceId}` [689]
  * `/clubs/{clubId}` [533]
  * `/team_assignments/{assignmentId}` [111]
